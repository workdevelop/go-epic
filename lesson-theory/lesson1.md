В екосистемі Go немає жорстко зафіксованого на рівні компілятора стандарту структури папок, як-от у Laravel чи Symfony. Проте світова спільнота розробників використовує один загальноприйнятий стандарт — Standard Go Project Layout.Для вашої команди PHP-розробників дуже важливо з першого дня побудувати проєкт правильно, щоб уникнути кругових імпортів (circular dependencies), які в Go є суворо забороненими на рівні компілятора.Нижче наведено ідеальну структуру папок для вашого репозиторію go-epic, адаптовану під наш проєкт Mage Arena.

```
📂 Канонічна структура файлів Go (Проєкт mage-arena)textmage-arena/
├── cmd/                      # Точки входу в додаток (тільки функція main)
│   └── arena/                # Назва нашого основного бінарника
│       └── main.go           # Головний файл, який запускає гру
│
├── internal/                 # Приватний код додатка (код, який не можна імпортувати ззовні)
│   ├── models/               # Наші структури даних (чисті сутності)
│   │   ├── position.go
│   │   ├── mage.go
│   │   ├── orc.go
│   │   └── world.go
│   │
│   ├── engine/               # Логіка гри (Ігровий цикл, механіка бою, рух)
│   │   └── loop.go
│   │
│   └── render/               # Логіка малювання в консолі (TUI, кольори)
│       └── terminal.go
│
├── pkg/                      # Публічні бібліотеки (опціонально, якщо пишете код для інших проєктів)
│
├── go.mod                    # Менеджер залежностей (аналог composer.json)
├── go.sum                    # Контрольні суми залежностей (аналог composer.lock)
└── README.md                 # План навчання та документація проєкту
```

🔍 Детальний розбір ключових папок для PHP-шників

1. Папка cmd/ (Точки входу) Що тут лежить: Тільки папки з назвами майбутніх виконуваних файлів (бінарників). Всередині кожної папки лежить main.go.Правило Go: У файлах всередині цієї папки завжди пишеться package main. Тут немає бізнес-логіки. Функція main() лише ініціалізує світ і запускає движок.Аналог в PHP: Це папка public/index.php у вебфреймворках або консольний скрипт artisan / bin/console.
2. Папка internal/ (Приватне серце проєкту)Що тут лежить: Уся бізнес-логіка, моделі та сервіси. Особливість ключового слова internal у Go полягає в тому, що компілятор фізично заборонить будь-якому сторонньому проєкту імпортувати код із цієї папки.Для чого це: Це захищає архітектуру від брудних хаків та випадкових зв'язків.
3. Файли go.mod та go.sum
Що тут лежить: Ваші залежності. Коли ви захочете встановити бібліотеку для графіки в консолі (наприклад, Lip Gloss), ви виконаєте команду go get ://github.com. Вона автоматично запишеться в go.mod.
Аналог в PHP: go.mod — це composer.json, а go.sum — це composer.lock.
  
⚠️ Головна пастка Go: Кругові імпорти (Circular Dependencies)
В PHP ви можете легко зробити так: Клас User викликає метод класу Order, а клас Order всередині себе викликає метод класу User. PHP-FPM це пробачить.
В Go це категорично заборонено. Якщо пакет engine імпортує пакет models, то пакет models не має права знати нічого про пакет engine. Якщо ви спробуєте це зробити, Go видасть помилку: import cycle not allowed і код не скомпілюється.
Як правильно будувати архітектуру на прикладі нашої структури:
Пакет internal/models — є повністю незалежним. Він нікого не імпортує. Він просто описує структури Mage, Orc, Position.
Пакет internal/engine — імпортує internal/models, щоб керувати цими юнітами.
Пакет internal/render — імпортує internal/models, щоб знати, де кого намалювати.
Файл cmd/arena/main.go — імпортує і models, і engine, і render, щоб склеїти їх разом.

📔 Теоретична частина. День 1: Структури як значення
При переході з PHP на Go ваша команда робить крок від динамічного середовища інтерпретатора (де багато процесів приховано «під капотом») до скомпільованої мови, яка дає повний контроль над залізом та пам'яттю вашого сервера.
Перший ментальний зсув, який потрібно зробити — повністю забути про класи та звичне ООП. В Go немає класів. Замість них використовуються структури (struct).
🧠 PHP-об'єкти vs Go-структури: Головна різниця
Щоб зрозуміти поведінку Go, згадаємо, як працює пам'ять у PHP.
Як це працює в PHP (Посилальна модель)
У PHP об'єкти (екземпляри класів) керуються через внутрішні покажчики (identifiers). Коли ви присвоюєте об'єкт новій змінній або передаєте його в аргумент функції, PHP не копіює сам об'єкт. Він копіює лише посилання на нього.

``` php// PHP код
$mage1 = new Mage();
$mage1->hp = 100;

$mage2 = $mage1; // Скопіювалось ПУСТОГО посилання, а не об'єкта!
$mage2->hp = 50; 

echo $mage1->hp; // Виведе 50, бо $mage1 та $mage2 вказують на ОДИН об'єкт у пам'яті.
```

Як це працює в Go (Модель значень)
В Go структура — це чистий тип даних, такий самий як звичайне число (int) чи рядок (string). Структура є значенням.
Коли ви присвоюєте одну структуру іншій або передаєте її у функцію, Go робить повну фізичну копію всіх даних цієї структури в нову ділянку оперативної пам'яті.

```go// Go код
mage1 := Mage{HP: 100}

mage2 := mage1 // Go повністю СКОПІЮВАВ дані з mage1 у mage2 (виділено нову пам'ять)
mage2.HP = 50

fmt.Println(mage1.HP) // Виведе 100! Оригінальний маг ніяк не постраждав.
```

Золоте правило дня для команди: У Go за замовчуванням копіюється абсолютно все. Будь-яке присвоєння чи передача в аргументи — це клонування даних.
🏗️ Детальний розбір моделей для Mage Arena
Для запуску нашого движка нам потрібно спроектувати 4 сутності (моделі). Оскільки в Go немає наслідування (ви не можете написати class Mage extends Unit), ми використовуємо композицію — збираємо великі структури з маленьких.

1. Модель Position (Координати)
Це найпростіша структура, яка не має аналогів у сутностях, але є фундаментальним "будівельним блоком" для гри.

```go
type Position struct {
    X int
    Y int
}
```
Підґрунтя: В PHP ви б, скоріш за все, використовували звичайний асоціативний масив ['x' => 1, 'y' => 2]. В Go це неприпустимо. Будь-яка сутність повинна мати строгий тип. Наявність типу Position гарантує, що компілятор не дозволить вам випадково передати туди текст або неіснуючий ключ.

2. Модель Mage (Маг) та Orc (Орк)Оскільки наслідування немає, ми впроваджуємо структуру Position безпосередньо всередину наших персонажів. Цей підхід в Go називається вбудовуванням (Embedding) або анонімними полями.
```go
type Mage struct {
    Position      // Вбудована структура. Маг автоматично отримує поля X та Y
    Health   int
    Mana     int
}

type Orc struct {
    Position      // Орк теж отримує поля X та Y через композицію
    Health   int
    Damage   int
}

```

Підґрунтя: Зверніть увагу, як оголошуються поля. Спочатку йде назва поля, а потім його тип (Health int). Це незвично після PHP (int $health), але до цього швидко звикаєш. Завдяки вбудовуванню Position, ви зможете звертатися до координат мага напряму: mage.X = 5, хоча технічно вони лежать всередині mage.Position.X.3. Модель World (Ігровий світ / Арена)
Ця структура є агрегатором всього нашого ігрового стану. Вона відповідає за розміри карти та зберігає списки живих юнітів.
```go
type World struct {
    Width  int
    Height int
	Mages  []Mage // Зріз (Slice) — аналог строго типізованого списку
	Orcs   []Orc  // Динамічний масив, який містить виключно структури Orc
}
```

### Підґрунтя для PHP-розробників (Важливо): ###

В PHP ви звикли створювати колекції об'єктів (наприклад, через Laravel Collections або кастомні класи-ітератори), де під капотом лежить масив посилань на об'єкти.
В Go поле Mages []Mage — це зріз значень. Це означає, що всі маги лежать у пам'яті комп'ютера один за одним, суцільним фізичним блоком. Це забезпечує просто космічну швидкість читання даних процесором (Cache Locality), яка для PHP є недосяжною через особливості роботи його Zend Virtual Machine.
