# 📔 Теоретична частина. Тиждень 2, День 3 (День 9): Обробка помилок як значення

Сьогодні ваша команда пройде через один із найважливіших архітектурних зсувів у Go. Ми повністю розберемо філософію обробки помилок.

## 🧠 Exceptions в PHP vs Errors як значення в Go

Щоб зрозуміти, чому творці Go обрали такий шлях, порівняємо, як обидві мови ставляться до нештатних ситуацій у коді.

### Як це працює в PHP (прихований потік керування)

В PHP, якщо метод не може виконати дію (наприклад, юніт намагається вийти за межі карти), ви викидаєте виключення:

```php
// PHP код
public function move(int $dx, int $dy): void {
    if ($this->isOutOfBounds($dx, $dy)) {
        throw new OutOfBoundsException("Юніт не може вийти за межі карти");
    }
    $this->x += $dx;
}
```

Будьте обачні, використовуючи код.

Проблема підходу: виключення створюють прихований потік керування. Метод `move()` каже, що він повертає `void`, але насправді він може "вибухнути" у будь-який момент. Розробник, який викликає цей метод, може забути обернути його в `try/catch`, і тоді весь додаток впаде (Fatal Error).

### Як це працює в Go (явний та прозорий потік)

В Go функції та методи можуть повертати декілька значень одночасно. Якщо метод може завершитися невдачею, він залізно повертає тип `error` останнім значенням у списку.

```go
// Go код
func (m *Mage) Move(dx, dy int) error {
    if nextXOutOfBounds || nextYOutOfBounds {
        return errors.New("вихід за межі карти") // Повертаємо помилку як результат
    }
    m.X += dx
    return nil // nil означає "помилки немає" (аналог null в PHP)
}
```

Будьте обачні, використовуючи код.

Перевага підходу: тип `error` — це вбудований інтерфейс Go. Будь-який розробник, який викликає метод `Move()`, на рівні сигнатури методу бачить: «ця дія може повернути помилку, я зобов'язаний її обробити».

## ⚙️ Зсув мислення: патерн Guard Clauses (явна перевірка)

Через відсутність `try/catch`, код на Go часто містить конструкції, які розробники жартома називають "скалою `if err != nil`". Для PHP-шників це спочатку виглядає незвично, але такий код є максимально читабельним: він виконується суто зверху вниз, без раптових "стрибків" по стеку викликів.

Ідіоматичний підхід Go вимагає обробляти помилку миттєво, використовуючи патерн Guard Clauses:

```go
err := mage.Move(1, 0)
if err != nil {
    // 1. Обробляємо помилку одразу (пишемо в лог, повертаємо клієнту, ігноруємо хід тощо)
    log.Println("Неможливо зробити хід:", err)
    return
}

// 2. Якщо помилки немає — спокійно продовжуємо щасливий шлях коду (happy path)
```

Будьте обачні, використовуючи код.

## 🏗️ Обробка помилок у Mage Arena: валідація ходів

До сьогоднішнього дня наш `World` сам перевіряв координати: він брав `RandomStep()`, рахував математику і, якщо все ок, викликав `Move()`. Це порушувало інкапсуляцію. Юніт має сам відповідати за свій рух і заявляти, якщо хід є неможливим.

Сьогодні ми перенесемо валідацію меж карти безпосередньо в методи `Move()` моделей `Mage` та `Orc`.

Помилка буде повертатися у двох випадках:
- юніт намагається вийти за зовнішні стіни карти;
- юніт намагається наступити на іншу перешкоду (якщо ми закладемо внутрішні бар'єри).

Движок гри (`World.Tick()`) буде викликати `Move()`, ловити цю помилку, і якщо вона є — просто ігнорувати хід цього конкретного юніта на поточному кадрі, залишаючи його на місці.

## 🎯 Що ми робимо на практиці в середу?

- кожен розробник створює свою персональну гілку за шаблоном `feature/{name}-day-9` (або `day-3-week-2` залежно від вашого внутрішнього Git-нотатка);
- імпортуємо стандартний пакет `errors` у файли моделей;
- оновлюємо інтерфейс `Unit`: метод `Move(dx, dy int)` тепер зобов'язаний повертати `error`;
- змінюємо реалізацію `Move()` всередині `mage.go` та `orc.go`: передаємо в метод розміри карти `Width` та `Height`, перевіряємо майбутні координати й повертаємо `errors.New("out of bounds")`, якщо юніт б'ється об стіну;
- у методі `World.Tick()` ловимо цю помилку. За бажанням додаємо текст помилки у наш `BattleLog` (наприклад, "Гендальф намагався пробити стіну карти"), щоб бачити її на екрані.

Обробка помилок — це візитна картка Go. Коли команда освоїть цей підхід, ви почнете писати значно надійніший бекенд-код.
