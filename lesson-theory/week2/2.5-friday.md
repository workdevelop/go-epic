# 📔 Теоретична частина. Тиждень 2, День 5 (День 11): Оператор defer та гарантоване закриття ресурсів

Сьогодні ваша команда освоїть одну з найважливіших ідіом мови Go — конструкцію **`defer`** (відкладений виклик). 

У PHP-FPM розробники рідко стикаються з витоками ресурсів, оскільки рантайнм повністю ізольований і «вмирає» за долі секунди після кожного веб-запиту. Проте в Go наш ігровий движок працює як довгоживучий процес. Якщо ми не закриємо за собою таймер, сокет, дескриптор файлу або не відновимо налаштування термінала — ці ресурси зависнуть у пам'яті сервера назавжди. 

Оператор `defer` створений для того, щоб зробити процес прибирання за собою простим, явним і захищеним від помилок розробника.

---

## 🧠 Як працює defer: Концепція та аналог у PHP

Ключове слово `defer` перед викликом функції каже компілятор: *«Не виконуй цю дію прямо зараз. Додай її у спеціальний стек відкладених завдань для поточної функції»*. 

Всі функції, помічені як `defer`, гарантовано виконаються **в самому кінці**, коли поточно функція (наприклад, `main()`) завершить свою роботу:
- Через явне повернення (`return`),
- Дійшовши до закриваючої фігурної дужки `}`,
- Або навіть якщо в програмі станеться аварійний збій (паніка / `panic`).

### 🔀 Порівняння з PHP: finally vs defer
В PHP для гарантованого виконання коду (наприклад, закриття з'єднання з базою даних) використовується важка конструкція `try/catch/finally`:

```php
// PHP код
\$db = MongoClient::connect();
try {
    // Якась складна логіка, що може кинути Exception
    \$db->query();
} finally {
    \$db->close(); // Цей код гарантовано виконається в кінці
}
```

В Go код виглядає значно лаконічніше та чистіше. Ви відкриваєте ресурс і **на наступному ж рядку** пишете команду для його закриття через `defer`. Вам не потрібні глибокі вкладеності блоків коду:

```go
// Go код
db := connectDB()
defer db.Close() // Миттєво задекларували закриття

// Спокійно пишемо бізнес-логику нижче, без try/catch
db.Query()
```

### 🔒 Важливе правило стеку: LIFO (Last In, First Out)
Якщо всередині однієї функції ви викликаєте кілька операторів `defer`, вони складаються в стек і виконуються у **зворотному порядку** (останній доданий виконається першим). 
Це ідеально для вкладених ресурсів: спочатку закриється файл, а потім — підключення до сервера, на якому цей файл лежить.

## 🏗️ Навіщо нам defer у Mage Arena: Робота зі станом термінала

У Вівторок (День 8) мы використали ANSI escape-коди, щоб сховати текстовий курсор (`\x1b[?25l`) та очистити екран, створюючи ілюзію анімації. 

Проте виник серйозний побічний ефект: якщо користувач перериває гру комбінацією клавіш `Ctrl + C` або програма завершується самостійно, текстовий курсор у терміналі **залишається невидимим**. Користувачу доводиться наосліп перезапускати свій термінал, бо його стан було пошкоджено нашою програмою.

У професійних TUI-додатках (Terminal User Interface) на Go є залізне правило: **при старті програми ми перемикаємо термінал у "сирий" бойовий режим, але через defer обов'язково реєструємо функцію відновлення початкового стану термінала.**

Сьогодні ми навчимо наш `main()` акуратно повертати термінал у дефолтний стан при будь-якому сценарії виходу з гри. Ми гарантовано:
1. Зупинимо та звільнимо фоновий таймер `time.Ticker`, щоб уникнути витоку пам'яті.
2. Повернемо текстовому курсору видимість (`\x1b[?25h`), щоб не псувати термінал користувача після закриття гри.

## 🎯 Що ми робимо на практиці в П'ятницю?

- кожен розробник створює свою персональну гілку за шаблоном `feature/{name}-day-11` (або `day-5-week-2` залежно від вашого внутрішнього Git-нотатка);
- На початку функції `main()` у файлі `cmd/arena/main.go` ми додаємо ANSI-команду ініціалізації гри (ховати курсор) та одразу під нею реєструємо відкладений виклик через `defer`, який поверне курсор на місце при виході.
- Оскільки ми використовуємо `time.NewTicker`, ми обов'язково пишемо `defer ticker.Stop()`, щоб рантайм Go очистив внутрішні ресурси таймера, коли ігровий цикл завершиться.
- Тестуємо гру: запускаємо її, граємо кілька секунд і перериваємо процес через `Ctrl + C`. Перевіряємо, що після виходу термінал працює ідеально, а курсор знову видимий.
