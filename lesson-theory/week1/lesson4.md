# 📔 Теоретична частина. День 4: зрізи (slices) та мапи (maps) замість масивів PHP

У PHP масив (`array`) — це універсальний інструмент. Він одночасно виконує роль списку, асоціативного масиву, черги (`queue`) та стеку. PHP-FPM ховає від розробника всю складність керування пам'яттю цього комбайна.

В Go, як у скомпільованій мові, для різних задач існують окремі, чітко оптимізовані типи даних. Сьогодні ми детально розберемо альтернативи PHP-масивам, які потрібні для управління нашими загонами магів та орків: зрізи (`slices`) та мапи (`maps`).

## 🧠 Масиви vs зрізи (slices): фундаментальна різниця

В Go є класичні масиви (`arrays`), але ви майже ніколи не будете використовувати їх у бізнес-логіці.

### Чому масиви Go не підходять для динамічної карти

Масив в Go має жорстко фіксовану довжину, яка є частиною його типу. Запис `[5]int` та `[10]int` — це два абсолютно різні типи даних, їх не можна порівняти чи передати в одну функцію. Масив не може розширюватись.

### Зріз (slice) — динамічний стандарт Go

Зріз (`slice`) — це динамічна обгортка над звичайним масивом. Ви вже використовували його в перші дні, записуючи поля як `[]Mage` (порожні квадратні дужки означають динамічний розмір).

Під капотом кожен зріз складається з трьох елементів (структура `SliceHeader`):

- `Pointer`: адреса пам'яті, де починається перший елемент у базовому масиві.
- `Length`: кількість елементів, які зараз є в зрізі. Повертається функцією `len(s)`.
- `Capacity`: максимальна кількість елементів, яку базовий масив може вмістити без виділення нової пам'яті. Повертається функцією `cap(s)`.

## 🔀 Порівняння додавання елементів: PHP vs Go

У PHP ви пишете `$array[] = $value;`, і інтерпретатор сам розширює пам'ять. В Go для цього використовується вбудована функція `append()`.

```go
// Створюємо порожній зріз орків
var orcs []Orc

// append() завжди повертає ОНОВЛЕНИЙ зріз. Це залізне правило!
orcs = append(orcs, Orc{Health: 100})
```

Що відбувається в пам'яті при `append`: якщо місткості (`capacity`) недостатньо, Go автоматично створює в пам'яті новий базовий масив (який зазвичай удвічі більший за попередній), копіює туди старі дані, додає новий елемент і повертає новий покажчик.

## 🗺️ Мапи (maps) — асоціативні масиви Go

Якщо вам потрібно діставати елементи не за індексом (`0, 1, 2`), а за текстовим чи числовим ключем (як `$array['mage_id']` в PHP), в Go використовуються мапи (`maps`).

Синтаксис оголошення мапи: `map[ТипКлюча]ТипЗначення`.

```go
// Створюємо мапу, де ключ — це ID (string), а значення — структура Mage
magesMap := make(map[string]Mage)

magesMap["id_45"] = Mage{Health: 100}
```

## ⚠️ Головні пастки мап для PHP-шників

- Мапи не впорядковані. Коли ви перебираєте мапу в циклі `for range`, черговість елементів щоразу буде випадковою. Go навмисно перемішує елементи при кожному циклі, щоб розробники не закладалися на порядок ключів (як це часто роблять в PHP).
- Перевірка на існування ключа. Якщо в PHP ви пишете `isset($array['key'])`, то в Go звернення до мапи повертає два результати: саме значення та булевий прапорець (знайдено / не знайдено).

```go
mage, exists := magesMap["non_existent_id"]
if !exists {
    fmt.Println("Мага не знайдено!")
}
```

## ⚙️ Зсув мислення: перебір через for range та безпека копіювання

В PHP `foreach ($array as $value)` копіює значення (якщо не вказано `&$value`). В Go цикл `for _, v := range slice` діє так само строго.

Важлива пастка: друга змінна в циклі `range` (`v`) — це завжди локальна копія елемента.

```go
// ПОМИЛКА: здоров'я орків у світі не зміниться!
for _, orc := range world.Orcs {
    orc.Health -= 10 // Ми змінюємо локальну змінну-копію "orc"!
}

// ПРАВИЛЬНО: зміна через індекс масиву
for i := 0; i < len(world.Orcs); i++ {
    world.Orcs[i].Health -= 10 // Змінюємо оригінал прямо в зрізі
}
```

## 🎯 Що ми робимо на практиці в четвер?

- Кожен розробник створює персональну гілку за шаблоном `feature/{name}-day-4`.
- Додаємо в структуру `World` метод `Tick()`, який буде симулювати один хід нашого ігрового всесвіту.
- Всередині `Tick()` ми послідовно перебираємо всіх магів та орків через правильні цикли (за індексами), змушуючи кожного зробити випадковий крок на `-1`, `0` або `+1` клітинку по осях `X` та `Y`.
- У файлі `main.go` ми запустимо цикл із 3-х послідовних "тіків" світу і виведемо в консоль історію переміщень нашої армії.
