# 📔 Теоретична частина. День 6: фінальна збірка MVP "Mage Arena v0.1"

Сьогодні ваша команда проведе перше велике 3-годинне практичне заняття (суботній спринт). Усі теоретичні знання, які ви здобули протягом робочого тижня — структури, вказівники, методи, зрізи та інтерфейси — об'єднаються в один працюючий програмний продукт.

Для розробників із досвідом у PHP цей день є переломним. Ви не просто пишете ізольовані класи чи окремі функції. Сьогодні ви виступаєте в ролі архітекторів системного рівня, створюючи повноцінний ігровий двигун, який самостійно керує станом об'єктів у довгоживучому процесі оперативної пам'яті комп'ютера.

## 🧠 Архітектура MVP: покрокова синхронізація (deterministic engine)

У наступну суботу (на тижні №2) ми навчимо гру працювати автономно в реальному часі за допомогою таймерів та очищення екрана. Проте для версії `v0.1` ми побудуємо покроковий двигун (turn-based / deterministic engine).

Кожен крок гри (`Tick`) відбуватиметься лише тоді, коли користувач натискає клавішу Enter у консолі. Це ідеальний архітектурний підхід для налагодження та тестування, оскільки ви зможете чітко відстежувати зміни в логах.

## 🔄 Анатомія одного «тіку» (Game Loop v0.1)

1. `Wait for Input`: програма зупиняється та чекає на команду користувача (`fmt.Scanln()`).
2. `AI Logic Processing`: світ перебирає всіх юнітів через інтерфейс `Unit`. Кожен живий юніт приймає рішення про випадковий крок на карті.
3. `Collision & Combat Detection`: світ аналізує нові координати. Якщо маг і орк опиняються на сусідніх клітинках (або на одній) — запускається бойовий метод `Attack()`.
4. `Clean up Dead Bodies`: юніти, чиє здоров'я впало до `0`, ігноруються або маркуються як мертві.
5. `Render Screen`: карта повністю перемальовується у терміналі, відображаючи нові позиції та поточні статистики (`Health`, `Mana`).

## 🛠️ Бойовий цикл: взаємодія об'єктів через інтерфейси

Одне з найважливіших інженерних рішень сьогодні — реалізація логіки атак. Оскільки в нашому зрізі `Units []Unit` всі персонажі сховані за абстрактним інтерфейсом, нам потрібно навчити їх взаємодіяти за універсальними методами.

```go
package models

type Unit interface {
    Move(dx, dy int)
    IsAlive() bool
    GetPosition() (int, int) // Go дозволяє повертати декілька значень одночасно!
    GetName() string
    GetDamage() int
    TakeDamage(amount int)
}
```

Завдяки цьому, коли під час аналізу карти ми виявимо, що два юніти стоять поруч, ми зможемо написати універсальний бойовий код, який працюватиме однаково як для дуелі маг проти орка, так і для битви орк проти орка:

```go
// Універсальна функція сутички всередині двигуна
func Battle(u1, u2 Unit) {
    damage := u1.GetDamage()
    u2.TakeDamage(damage)
    fmt.Printf("⚔️ [%s] атакує [%s] і завдає %d шкоди!\n", u1.GetName(), u2.GetName(), damage)
}
```

## ⚙️ Зсув мислення: спільна колізія замість ізольованих HTTP-запитів

При розробці на PHP-FPM ви зазвичай будуєте код навколо ізольованого контексту: «один користувач робить одну дію над своєю сутністю у базі даних».

В ігровому двигуні Go ви керуєте цілісною екосистемою, де дії одного об'єкта миттєво впливають на інший в межах однієї програми. Якщо маг кудись наступив — він фізично заблокував цю клітинку для орка. Якщо орк вдарив мага — здоров'я мага зменшилося в ту саму мікросекунду для всієї системи розрахунку.

Саме сьогодні команда остаточно закріпить розуміння того, що Go-додаток — це живий організм, який постійно мутує свій стан у реальному часі.

## 🎯 План роботи на суботній 3-годинний спринт

- Година 1: мердж та підготовка бази. Капітан збирає пул-реквести за тиждень. Створюється фінальна версія інтерфейсу `Unit`. Маг та Орк доопрацьовуються, щоб повністю відповідати цьому інтерфейсу.
- Година 2: реалізація двигуна (`internal/engine/game.go`). Пишемо логіку ініціалізації світу з 5 магами та 5 орками на випадкових координатах. Пишемо метод `Tick()`, який розраховує рух, виявляє сутички та зменшує здоров'я юнітів.
- Година 3: інтеграція та рендеринг. Налаштовуємо красиве консольне виведення: карту, лог битви під картою та таблицю лідерів (хто ще живий). Запускаємо гру, тестуємо покроковий бій за допомогою клавіші Enter.
