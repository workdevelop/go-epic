# 🧠 Що таке вказівник: аналогія для PHP-розробників

В PHP ви не керуєте адресами пам'яті вручну, але під капотом мови відбувається те саме.

## Як це працює в PHP (Приховані посилання)

В PHP, коли ви передаєте об'єкт у функцію, передається його внутрішній ідентифікатор (посилання). Ви можете думати про це як про ярлик (shortcut) на робочому столі. Якщо ви змінюєте файл через ярлик, змінюється сам файл.

В PHP єдиний спосіб скопіювати об'єкт — явно викликати ключове слово `clone`.

## Як це працює в Go (явні вказівники)

В Go все навпаки: за замовчуванням робиться повний `clone`. Щоб передати "ярлик", ви повинні зробити це явно за допомогою двох операторів:

- `&` — оператор взяття адреси. Перетворює значення на "ярлик" (вказівник). Каже: "Мені не потрібні самі дані, дай мені адресу комірки пам'яті, де вони лежать".
- `*` — оператор типу вказівника. Вказує компілятору, що змінна зберігає не дані, а адресу. `*Mage` читається як "вказівник на Мага".

## Поняття

| PHP аналог | Go синтаксис | Що це означає |
| --- | --- | --- |
| Значення | `mage := Mage{}` | Сам об'єкт із даними |
| Вказівник | `ptr := &mage` | Адреса, де лежить об'єкт |
| Тип вказівника | `func Move(m *Mage)` | Функція чекає адресу, а не копію |

## 🛠️ Мутація стану: чому це важливо для Mage Arena

Поглянемо на дві функції руху орка. Одна написана звичним для PHP-шника стилем (процедурно, без думок про пам'ять), а друга — ідіоматично для Go.

### Варіант 1: Помилка копіювання (без вказівника)

```go
// Тут Orc — це значення. Передається ПОВНА КОПІЯ.
func MoveOrcWrong(o Orc) {
    o.X += 1 // Змінюється координата всередині копії
    // Функція завершилась, копія видалилась із пам'яті. Оригінал не змінився.
}
```

Будьте обачні, використовуючи код.

### Варіант 2: Правильна мутація (з вказівником)

```go
// *Orc означає, що функція приймає АДРЕСУ оригінального орка
func MoveOrcCorrect(o *Orc) {
    o.X += 1
    // Go автоматично розуміє, що треба піти за адресою і змінити оригінал.
    // Примітка: у мовах типу C/C++ довелось би писати (*o).X += 1, але Go робить розіменування автоматично.
}
```

Будьте обачні, використовуючи код.

## ⚙️ Зсув мислення: Garbage Collector та стек vs купа (stack vs heap)

В PHP-FPM ви не думаєте про очищення пам'яті: запит завершився, і PHP повністю вичищає всю пам'ять, яка була виділена під скрипт.

В Go процес гри живе годинами (або днями). Тому важливо розуміти, куди компілятор ховає ваші структури:

- Стек (stack): надшвидка пам'ять. Коли ви передаєте структури як значення (копії), вони зазвичай кладуться на стек і моментально видаляються, як тільки функція завершує роботу. Це не навантажує збирач сміття.
- Купа (heap): повільніша пам'ять. Коли ви використовуєте вказівники (`&`), об'єкт "втікає" в купу (escape analysis). Він залишається там жити доти, доки на нього є хоч один вказівник у грі. Потім прийде Garbage Collector і очистить його.

Правило дня для команди:

- Не використовуйте вказівники повсюдно лише тому, що "в PHP об'єкти працюють так".
- Якщо структуру (наприклад, `Position`) потрібно просто передати для математичного розрахунку відстані й не треба змінювати — передавайте її як значення (без `*`). Це розвантажить процесор і збирач сміття.
- Якщо об'єкт має змінювати свій стан (здоров'я, координати) — передавайте вказівник.

## 🎯 Що ми робимо на практиці у вівторок?

- Створюємо окрему гілку `feature/{your-name}-day-2`.
- Виносимо логіку руху юнітів в окремі функції `MoveMage(m *Mage, dx, dy int)` та `MoveOrc(o *Orc, dx, dy int)`, де `dx` та `dy` — це величина зміщення (наприклад, `+1` або `-1`).
- Модифікуємо координати першого мага і першого орка у нашому світі `World`.
- Виводимо карту в консоль до руху і після руху, щоб переконатися: літери `M` та `O` дійсно перемістилися на нові клітинки ASCII-мапи.
