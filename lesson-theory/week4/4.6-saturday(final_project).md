## 🧠 Архітектура Фінального Релізу: Чисте розділення процесів

Сьогодні наш додаток остаточно розділяється на два незалежні шари:
1. **Engine Core (Фоновий движок):** Гра продовжує жити своїм автономним асинхронним життям в оперативній пам'яті додатка. Горутини-юніти бігають, канали передають повідомлення про ходи, оператор `select` керує таймаутами та колізіями битв.
2. **REST Web API Interface (Зовнішній інтерфейс):** Поверх движка розгортається мережевий шар. Клієнти з усього світу можуть керувати цією ареною через стандартні HTTP-запити.

### 📐 Проєктування REST API нашої арени:
Щоб сервіс став повноцінним REST-додатком, ми реалізуємо канонічну матрицю HTTP-методів та маршрутів:
- `GET /api/state` — Повертає поточне тактичне поле та координати живих юнітів (JSON).
- `GET /api/history` — Зчитує з бази даних SQLite/Postgres історію всіх зіграних матчів.
- `POST /api/spawn` — Дозволяє клієнту на льоту додати нового мага чи орка на арену, передавши JSON з ім'ям та координатами. Наш API-хендлер зчитає цей запит і миттєво запустить для нового героя його власну горутину `go unit.Brain()`.
- `POST /api/reset` — Повністю перезапускає гру, очищує мапу, створює новий всесвіт і скидає логи.

## ⚙️ Нова інженерна концепція: Graceful Shutdown (Чисте вимкнення)

Для Production-Ready сервісів у сучасних хмарах (на кшталт Docker/Kubernetes) критично важливо вміти правильно завершувати роботу. 

### Як це працює в PHP-FPM
Якщо ваш сервер йде на перезавантаження, Kubernetes просто вбиває контейнер. PHP-FPM процеси, які виконувалися в цей момент, обриваються миттєво. Якщо скрипт не встиг записати щось у базу даних — дані будуть втрачені або пошкоджені.

### Як це працює в Go
Оскільки Go-додаток є самодостатнім процесом, при зупинці сервера операційна система надсилає йому спеціальний сигнал (наприклад, `SIGTERM` або `SIGINT` при натисканні `Ctrl+C`). В Go ми можемо **перехопити цей сигнал** за допомогою вбудованого пакету `"os/signal"`.

```go
// Створюємо канал для перехоплення сигналів від операційної системи
sigChan := make(chan os.Signal, 1)
signal.Notify(sigChan, os.Interrupt, syscall.SIGTERM)

// Цей рядок заблокує виконання програми, поки ОС не скаже "Час вимикатися"
<-sigChan 

// 🚀 Починається Graceful Shutdown:
// 1. Кажемо веб-серверу припинити приймати нові HTTP-запити.
// 2. Даємо горутинам-юнітам добігти свій останній хід та акуратно завершити цикли.
// 3. Зберігаємо поточний стан незавершеного матчу в базу даних.
// 4. Закриваємо пули з'єднань з БД через db.Close().
```
Завдяки Graceful Shutdown наш сервіс ніколи не втратить дані клієнтів і не пошкодить файли бази даних під час планових релізів або оновлень інфраструктури.
