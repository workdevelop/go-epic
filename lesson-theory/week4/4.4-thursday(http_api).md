## 🧠 Apache/Nginx + PHP-FPM vs Вбудований HTTP-сервер Go

У світі PHP веб-розробка неможлива без зовнішнього інфраструктурного «оркестру». 

### Як це працює в PHP (Багатошарова інфраструктура)
Коли клієнт робить запит до вашого PHP API, запит спочатку приймає веб-сервер (наприклад, `Nginx`). Він відповідає за SSL-сертифікати, статичні файли та HTTP-протокол. Потім Nginx через FastCGI-протокол перенаправляє цей запит до пулу процесів `PHP-FPM`. PHP-FPM піднімає чистий потік коду, ваш фреймворк (Laravel/Symfony) парсить запит, генерує JSON, віддає його назад і помирає.

### Як це працює в Go (Самодостатній бінарник)
В Go **HTTP-сервер вбудований безпосередньо в стандартну бібліотеку мови** (пакет `"net/http"`). Вам не потрібні ні Nginx, ні Apache, ні окремі менеджери процесів типу PHP-FPM. 
- Ваш додаток на Go — це і є веб-сервер. 
- Він самостійно відкриває TCP-порт (наприклад, `:8080`), сам слухає мережеву карту, сам приймає HTTP-запити від тисяч клієнтів одночасно.
- На кожен вхідний запит рантайм Go автоматично запускає **нову ізольовану горутину**, що забезпечує колосальну паралельність розробки «з коробки» без жодних налаштувань.

## ⚙️ Робота з JSON: Серіалізація в Go (Marshalling)

В PHP перетворення масиву чи об'єкта в JSON робиться в один рядок за допомогою функції `json_encode($data)`. В Go, через її строгу статичну типізацію, цей процес влаштований дещо інакше і називається **Marshalling (маршалінг)**.

Для серіалізації структур у JSON використовується вбудований пакет `"encoding/json"`. Щоб компілятор знав, які ключі мають бути в фінальному JSON-об'єкті, ми використовуємо спеціальні **структурні теги (Struct Tags)**:

```go
type Position struct {
    // Тег `json:"x"` каже: у JSON це поле буде називатися маленькою літерою "x"
    X int `json:"x"` 
    Y int `json:"y"`
}
```

### 🚨 Найважливіше архітектурне правило:
Go серіалізує в JSON **тільки експортовані (публічні) поля**, які починаються з **Великої літери**. Якщо ви назвете поле структури з маленької літери, пакет `encoding/json` просто проігнорує його, і в фінальному JSON клієнт нічого не побачить.

## 🏗️ Архітектура ендпоінту `/state` у Mage Arena

Сьогодні ми зупинимо безкінечний рендеринг карти в консоль. Натомість наш головний потік `main()` запустить веб-сервер:
```go
http.HandleFunc("/state", func(w http.ResponseWriter, r *http.Request) {
    // Тут ми будемо віддавати стан світу
})
http.ListenAndServe(":8080", nil) // Сервер починає слухати порт 8080
```

Гра продовжує жити своїм життям: горутини-юніти бігають на задньому плані в оперативній пам'яті додатка, б'ються та пишуть логи. Але тепер, коли зовнішній користувач (або фронтенд-додаток) робить HTTP-запит `GET http://localhost:8080/state`, наш Go-сервер миттєво бере поточний об'єкт `World` із пам'яті, перетворює його в чистий JSON і віддає клієнту.

## 🎯 Що ми робимо на практиці в Четвер?

- Кожен розробник створює свою персональну гілку за шаблоном `feature/{name}-day-22` (або `day-4-week-4` залежно від вашого внутрішнього Git-нотатка);
- Додаємо JSON-теги до всіх наших структур даних: `Position`, `Mage`, `Orc`, `World`;
- У файлі `cmd/arena/main.go` підключаємо пакет `"net/http"` та `"encoding/json"`;
- Створюємо HTTP-хендлер для маршруту `/state`;
- Всередині хендлера встановлюємо правильний заголовок відповіді `w.Header().Set("Content-Type", "application/json")`;
- Передаємо об'єкт `world` у функцію `json.NewEncoder(w).Encode(world)`;
- Запускаємо проєкт, відкриваємо браузер або Postman за адресою `http://localhost:8080/state` і спостерігаємо, як наш ігровий всесвіт перетворився на сучасне високопродуктивне Web API.
