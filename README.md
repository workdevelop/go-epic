# Mage Arena — навчальний план з Go

Цей документ — структурований план навчання для команди PHP-розробників, які переходять на Go через створення термінального ігрового движка Mage Arena.

## Мета курсу

За 4 тижні команда навчиться:
- мислити в термінах Go-структур, а не PHP-об’єктів;
- працювати з вказівниками, слайсами та методами;
- будувати довгоживучий ігровий цикл;
- розуміти конкурентність через горутини, канали та mutex;
- оформлювати проєкт як production-ready Go-додаток.

## Формат занять

- Понеділок–пʼятниця: 1 година на день;
- Субота: 3 години;
- Кожен день має одну чітку тему та одне практичне завдання.

## Тиждень 1. Памʼять, типи та заміна ООП

### Мета тижня
Зрозуміти, як Go працює з памʼяттю, чому структури є значеннями, і як замінити звичні PHP-об’єкти на Go-дані та поведінку.

### Понеділок — Структури як значення
- Ключова тема: у PHP об’єкти передаються за посиланням, а в Go структури копіюються.
- Практика: створіть моделі `Position`, `
`, `Orc`, `World` і виведіть ASCII-карту 10x10 у консоль.
- Важливо: покажіть, що зміна даних через копію не змінює оригінал.

### Вівторок — Вказівники
- Ключова тема: для зміни оригінального стану потрібен вказівник.
- Практика: реалізуйте `MoveMage` і `MoveOrc` через вказівники.
- Зсув мислення: у Go ви явно вирішуєте, копіюєте дані чи змінюєте оригінал.

### Середа — Методи структур
- Ключова тема: Go не має класів, але має методи, прив’язані до структур.
- Практика: перенесіть логіку руху та урону в методи.
- Приклад: `func (o *Orc) Move(dx, dy int)`.

### Четвер — Слайси та мапи
- Ключова тема: замість PHP-масивів у Go використовують слайси та мапи.
- Практика: зберігайте магів і орків у слайсах і додайте простий `Tick()`.

### Пʼятниця — Інтерфейси
- Ключова тема: Go реалізує інтерфейси неявно.
- Практика: створіть інтерфейс `Unit` і зберігайте різних юнітів в одному слайсі.

### Субота — MVP Mage Arena v0.1
- Практика: створіть базову гру з 5 магами і 5 орками.
- Можливості: рух, атака, простий бойовий цикл у консолі.

## Тиждень 2. Довгоживучий процес і TUI

### Мета тижня
Перейти від моделі «запит → відповідь» до довгоживучого CLI-додатка, який працює в реальному часі.

### Понеділок — Game loop і `time.Ticker`
- Ключова тема: Go-програма може працювати безперервно.
- Практика: створіть цикл, який кожні 200 мс оновлює стан гри.

### Вівторок — ANSI-коди та очищення екрана
- Ключова тема: для анімації потрібно очищати екран або переміщувати курсор.
- Практика: реалізуйте `clearScreen()` і перерисовуйте карту без скролу.

### Середа — Обробка помилок як значення
- Ключова тема: у Go помилки повертаються як `error`, а не викидаються через винятки.
- Практика: зробіть `Move()` таким, що повертає помилку при виході за межі карти.

### Четвер — Go Modules і пакети
- Ключова тема: Go використовує `go.mod` і `go.sum`.
- Практика: розділіть код на пакети: `models`, `engine`, `render`.

### Пʼятниця — `defer` і закриття ресурсів
- Ключова тема: `defer` допомагає чисто завершувати гру.
- Практика: відновлюйте стан терміналу при виході з програми.

### Субота — TUI-версія гри
- Практика: додайте стилізацію консолі, бічну панель зі статистикою та логом боїв.

## Тиждень 3. Горутини, канали та спільний стан

### Мета тижня
Зламати синхронне мислення PHP-FPM і навчитися працювати з конкурентністю в Go.

### Понеділок — Горутини
- Ключова тема: горутини — це легкі потоки для паралельної логіки.
- Практика: кожен юніт працює у власній горутині.

### Вівторок — Race conditions
- Ключова тема: кілька горутин можуть одночасно змінювати один стан.
- Практика: запустіть гру з `go run -race` і знайдіть проблеми.

### Середа — `sync.Mutex`
- Ключова тема: mutex захищає спільний стан.
- Практика: додайте `sync.Mutex` до `World` і захистіть карту.

### Четвер — Канали
- Ключова тема: канали — це безпечний спосіб передачі повідомлень між горутинами.
- Практика: створіть канал подій і перенесіть дії юнітів через нього.

### Пʼятниця — `select` і таймаути
- Ключова тема: `select` дозволяє одночасно чекати кілька каналів.
- Практика: обробляйте тікер рендеру та події юнітів у одному циклі.

### Субота — Масштабування арени
- Практика: збільшіть карту і запустіть багато юнітів у конкурентному режимі.

## Тиждень 4. Архітектура, тести та перехід до web

### Мета тижня
Оформити проєкт у стилі production-ready, покрити код тестами і підготуватися до веб-інтеграції.

### Понеділок — Структура проєкту
- Ключова тема: у Go проєкт краще розділяти на пакети.
- Практика: структуруйте код у `cmd/arena`, `internal/engine`, `internal/models`.

### Вівторок — Табличні тести
- Ключова тема: Go має вбудовані тести через `go test`.
- Практика: напишіть тести для руху, бою та валідації меж карти.

### Середа — Бенчмарки
- Ключова тема: Go дозволяє вимірювати продуктивність.
- Практика: заміряйте швидкість пошуку ворога і оптимізуйте алгоритм.

### Четвер — HTTP API
- Ключова тема: Go має вбудований HTTP-сервер.
- Практика: додайте ендпоінт `/state`, який віддає стан гри у JSON.

### Пʼятниця — Робота з БД
- Ключова тема: можна підключати SQLite або PostgreSQL через `database/sql`.
- Практика: зберігайте стан матчів у базі.

### Субота — Фінальний проєкт
- Практика: перетворіть гру на backend-сервіс з REST API та збереженням стану.
